# LeetCode 13. 罗马数字转整数 (Roman to Integer)

## 1. 挑战点 (Challenge Points)
* **基础映射转换**：需要将无状态的罗马字母转化为有状态的阿拉伯数字。由于每种字母代表的固定数值不会改变，首要任务是建立一个准确无误的哈希表（或字典）来进行常数时间 O(1) 的查询。
* **特殊减法规则识别与处理**：这是本题的灵魂所在。罗马数字正常情况是从大到小排列（如 `VI` = 6），此时直接将字符代表的数字相加即可。但为了避免四个相同字符连写（如不写 `IIII` 而是写 `IV`），存在小数字写在大数字左边的情况。程序必须具备“向前看一步”的能力，判断当前字符与后一个字符的大小关系，从而决定当前字符是应该“被加上”还是“被减去”。
* **边界条件防范**：在进行“向前看一步”（即读取索引 `i+1` 的字符）时，极易发生数组或字符串越界异常。需要通过循环条件或索引判断，确保访问最后一个字符时不会触发越界。

## 2. 解题思路 (Ideas)
本题主要有两种非常经典的思路，这里以我们之前讨论的“从左到右遍历”为主，并辅以“从右到左”的思路作为拓展：

* **思路一：从左到右遍历（正向思维）**
    1. 首先建立包含所有 7 个基本罗马字符的字典映射表。
    2. 初始化一个 `total` 变量用于累加结果，获取字符串长度 `n`。
    3. 遍历字符串，对于每一个字符，判断其右侧是否还有字符（`i < n - 1`）。
    4. 如果右侧有字符，并且**当前字符的值小于右侧字符的值**（例如 `I` < `V`），说明遇到了特殊的减法规则。此时，将 `total` 减去当前字符的值。
    5. 在其他所有情况下（包含当前值大于等于右侧值，或者是最后一个字符），说明遵循正常的加法规则，将 `total` 加上当前字符的值。

* **思路二：从右到左遍历（逆向思维 - 拓展）**
    这种思路的巧妙之处在于不需要处理越界问题。从最后一个字符开始向左遍历，用一个变量记录前一个遍历到的字符值。如果当前字符值小于右侧记录的值，就减去它；否则加上它。

## 3. 代码实现 (Code)
```python
class Solution:
    def romanToInt(self, s: str) -> int:
        # 1. 建立基础的字符到数值的映射表，保证 O(1) 的查询效率
        roman_map = {
            'I': 1, 
            'V': 5, 
            'X': 10, 
            'L': 50, 
            'C': 100, 
            'D': 500, 
            'M': 1000
        }
        
        total = 0
        n = len(s)
        
        # 2. 逐个遍历字符串中的每个字符
        for i in range(n):
            # 3. 核心逻辑判断
            # i < n - 1 确保了当 i 指向最后一个字符时，不会去取 s[i+1] 导致越界报错
            # roman_map[s[i]] < roman_map[s[i+1]] 用于识别如 IV, IX, XL 等特殊情况
            if i < n - 1 and roman_map[s[i]] < roman_map[s[i+1]]:
                # 触发减法规则：当前较小的数字在较大数字的左边
                total -= roman_map[s[i]]
            else:
                # 触发加法规则：正常由大到小排列，或者是最后一个字符
                total += roman_map[s[i]]
                
        # 4. 返回最终累加计算得到的整数结果
        return total
```

## 4. 复杂度分析 (Complexity)
* **时间复杂度：O(n)**。其中 n 是输入字符串 `s` 的长度。算法只需要将输入字符串从头到尾遍历一次，在每次循环中，字典查询、数值比较和加减运算的时间复杂度均为 O(1)。因此总体时间复杂度随字符串长度呈线性增长。*（注：由于 LeetCode 题目限制了罗马数字最大为 3999，即字符串长度不会超过 15，所以在严谨的算法理论中也可视为 O(1) 时间复杂度，但通常我们按 O(n) 来回答面试官。）*
* **空间复杂度：O(1)**。算法在执行过程中只额外开辟了一个固定大小的字典 `roman_map`（包含 7 个键值对）以及常数个整型变量（`total`, `n`, `i`）。这些占用的内存空间不会随着输入字符串长度的增加而变大，因此空间复杂度为 O(1)。
